# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Pitch Bend Texture** (called **Doppler Saturator** up to 1.2; renamed in 1.3 at the user's request, the folder, repo, CMake target and class names stay `DopplerSat`): a JUCE (CMake) VST3 plugin, split off from Multiband Saturator (`../MultibandSat`, repo `SofusLindberg/MultibandSatV2`) on 2026-11-03. It is one band of Multiband Saturator's zero-latency engine (`satdsp::Engine`, the "0 ms - 24 / 48 dB/oct" modes, plus a 96 dB/oct mode since 1.2), moved from side to side by an LFO. A minimum-phase crossover that moves rotates the phase of the dry sum over time, so the pitch bends while the band moves. That is the Doppler effect, used here on purpose (the user: "Dobbler-effekt (ptitch ændres, når man trækker båndet henover frekvenserne) [...] er faktisk super fedt"). Built on Windows/MSVC; since 1.5 the code also builds as AU + VST3 on macOS (only via `.github/workflows/mac.yml`, there is no Mac here). Remote: `https://github.com/SofusLindberg/DopplerSat` (private).

## Same rules as Multiband Saturator

Read `../MultibandSat/CLAUDE.md` for the shared workflow. In short:
- **`FREMDRIFT.md`** (Danish, newest entry first) is the progress log. At session start, read it and tell the user where we got to. Log every prompt in the same turn. "Gem og luk" = log, commit, push, install (verified), and ask the user to type `/exit`.
- **`KRAV.md`** lists every requirement. Never remove or change one unless the user explicitly asks. Add new requests with the date and the user's words.
- Every installed version gets its own number: bump the minor version in `CMakeLists.txt` (`project(DopplerSat VERSION 1.x.0)`) before each new install. CMake derives `PRODUCT_NAME "Pitch Bend Texture 1.x"` (1.0–1.2: "Doppler Saturator 1.x") and `PLUGIN_CODE D1xx` (Multiband Saturator uses `M3xx`, same manufacturer code `Dtnv`). Never delete old versions. Verify the install by comparing file hashes.
- Commit and push yourself after every completed prompt with changes (Danish commit message).
- Code comments in Danish with ASCII spelling (`aa`/`oe`/`ae`), JUCE formatting style. `.ps1` files ASCII only (PowerShell 5.1 reads them as ANSI).

## Layout

- `CMakeLists.txt` + `Source/`. JUCE **9.0.3** must be the sibling folder `../JUCE` (shared with MultibandSat).
- `Source/SatDsp.h` is a **copy** of MultibandSat's `SatDsp.h` (3.18). Changes: (1.2) `kPhaseZl96` and `zlN6` (24 → n6 4, 48 → 8, 96 → 16), used by `zlSpec`; (1.5) `<emmintrin.h>` only on x86, otherwise `Source/SimdShim.h` (the 13 SSE2 functions SatDsp uses, one lane at a time, in namespace `satdsp`). The shim is bit-identical to SSE2 as long as there is no FMA (`-ffp-contract=off` for non-MSVC in CMakeLists). Check it on Windows with `cmake -B build-shim -DDS_FORCE_SIMD_SHIM=ON` + `HostSmoke --compare` (1.5: "SAMME LYD"). Since 1.1 the sound uses `Source/DopplerCore.h` (crossover design helpers, `Biquad2` / `ApChain2` from SatDsp.h); the editor still uses `makeCurveModel` to draw the band. Changes in SatDsp.h do not reach Multiband Saturator, and vice versa.
- `Source/PluginProcessor.*`: 13 parameters (`freq`, `amount` (shown as "Sweep" since 1.4), `width` (shown as "Band Size" since 1.4), `mode`, `rate`, `sync`, `syncrate`, `shape`, `offset`, `drywet`, `outgain`, `bypass`, and since 1.6 `pause` (the LFO phase stops advancing and, in Sync, stops following the host; on release Sync jumps back to the bar and the speed limit glides the edges there)). 1.8 had a 14th, `smooth` ("Smooth Peaks", default off); since 1.9 Smooth Peaks is always on and the parameter is gone (user, 2026-11-10: they could not hear a difference). **Smooth Peaks:** a second `satdsp::DopplerCore refCore` runs on the same oversampled input with the band limited to the old speed (`modeMaxSpeed`, i.e. like 1.6); the wet signal may peak at most `kSmoothCeilDb` = 3 dB above refCore's peak envelope (instant attack, 100 ms release; gain down 0.3 ms, up 60 ms). Slow rates are untouched because both engines are equal there. Tried first and rejected (2026-11-10): short RMS vs dry (peaks only fell 0–2 dB) and peaks vs dry (touched a saw at 0.25 Hz by up to −19 dB, because the allpasses change the waveform's crest factor even when still). Measured: worst peak 1.65 → 1.14 for a 0.6 input (+8.8 → +5.6 dB). **1.9 CPU (bit-identical to 1.8 with Smooth on, all 16 `--compare` steps):** (a) `refSame`: while refCore's whole state equals core's and both get the same edges, refCore is not run and its peaks are taken from core's output; when the edges first differ, `refCore = core` is copied *before* `core.setParams`, so refCore continues exactly as if it had always run; `DopplerCore::sameStateAs` (everything except h23) checks each chunk with equal edges whether they are equal again. In practice they only become equal again after Bypass, a mode change or `prepareToPlay` (after a Frequency jump, Square transitions or Pause they stay different in the last bits, even after silence). (b) `DopplerCore::processPair` runs both engines in one loop and computes h23 (band 2+3's static allpasses) once, because it gets the same input, has the same coefficients and is reset at the same moments. Measured with `--benchone` (512 blocks): slow Sine 2.29 % (1.8: 2.25 off / 3.58 on), after a jump 2.79 % (1.8 on: 3.75), Sine 12 Hz Sweep 100 % 2.75 % (1.8: 2.36 off / 3.71 on). `drive` and `type` were removed in 1.1 (user request: no saturation). `mode` has three choices since 1.2 (0 = 24, 1 = 48 (default), 2 = 96 dB/oct; `kNumModes`, `modePhase`, `modeMaxSpeed`). A new mode must go at the end, so saved sessions keep their index. `getBypassParameter()` returns `bypass`, so it is the DAW's bypass too. Never rename IDs. Since 1.4: buses stereo → stereo, mono → mono and mono → stereo (mono runs the stereo engine with a copy of the left channel in a `kChunk` scratch array, so stereo stays bit-identical), and `getTailLengthSeconds()` = 2 s (longest measured ring-out 1.32 s to −80 dB at 20 Hz, 0.1 oct, 96 dB/oct).
- `Source/PluginEditor.*`: fixed 900 × 600 window in Multiband Saturator's design 2A (`HardwareLook` copied). Display (`PlotArea`, output spectrum only), `LfoView` (the LFO curve with a moving dot) and, since 1.9, three modules (`layout::widths` 0.33 / 0.41 / 0 / 0.26, the Edges slot has width 0 and is skipped; knob spacing about 112 / 108 / 102 px): LFO, Band and Output. The three edge buttons "24 / 48 / 96 dB/oct" are a column (`layout::edgeColW` 118, height 20, 25 px apart, at module y 43 / 68 / 93) on the right of Band, beside the two LCDs (narrowed), with a silk "Edges" label and the "?" help box (copied from Multiband Saturator) at the top; the top and bottom buttons' centres line up with the two LCDs' centres. Up to 1.8 Edges was its own module with `SlopeView` ("Edge steepness", −24 / −48 / −96 dB at +1 oct), removed in 1.9 at the user's request after the mockup; the "0 ms - " prefix was dropped in 1.3 because all three are 0 ms. Bypass is placed from the centre of `modeButtons[0]` (user, 1.2: it must line up with the first edge button's middle), so it lines up with the Sweep LCD. The two LCDs in Band are labelled "Sweep" and "Band Size" (edges right now) since 1.5, matching the knobs. **Typing in the Sweep LCD (1.10):** `LcdText::onTyped` / `beginEdit`: clicking a number (left of the middle of " - " = low) opens a `juce::TextEditor` over just that number (Enter applies, Esc cancels, Tab applies and opens the other number, focus loss or another click on the LCD applies; unchanged text does nothing; the field is deleted asynchronously). `parseHz` reads "180", "1.2k", "1,2 kHz". `DopplerSatEditor::applySweepText` keeps the other end as displayed (offset included, clamped to 20 Hz - 20 kHz) and sets Frequency and Sweep in one gesture from `DopplerSatProcessor::sweepForEnds` (path log2 F + v A for v from max(-1, off-1) to min(1, off+1); A rounded to Sweep's 0.1 % step, F from the end that must stay; wider than Sweep 100 % = the typed end wins; low >= high = rejected). ## Build, test and install

`cmake` is not on PATH: use Visual Studio's own, `C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe` (from PowerShell). There is no Python either.

```sh
cmake -B build -G "Visual Studio 18 2026"
cmake --build build --config Release --target DopplerSat_VST3
cmake -S tests/host -B tests/host/build
cmake --build tests/host/build --config Release
tests/host/build/HostSmoke_artefacts/Release/HostSmoke.exe "build/DopplerSat_artefacts/Release/VST3/Pitch Bend Texture 1.10.vst3"
tests/host/build/HostSmoke_artefacts/Release/HostSmoke.exe "build/DopplerSat_artefacts/Release/VST3/Pitch Bend Texture 1.10.vst3" --compare "<copy of the previous version .vst3>"
tests/host/build/EditorShot_artefacts/Release/EditorShot.exe "<folder>"
```

## How it works

- **Engine use:** the sound is `satdsp::DopplerCore`: what `satdsp::Engine` does at 0 % drive (Engine's BandSat is off then, so the output is only the dry sum T = tch(band1(h23(x))), the allpasses of all crossovers). Only band `kBand` (1) moves; bands 0, 2 and 3 are parked far outside the audible range (10–12 Hz and 40–45 % of the processing rate), so their crossovers are static biquad allpasses (`ApChain2`) and add no pitch change. Since 1.7 band 1's four crossovers are `SvfXover` (TPT-SVF allpasses, same transfer function as `designXoverAp` at rest; g = tan(π fc / fs) glides linearly per sample from chunk to chunk), so the edges can move very fast without level jumps. 1.0–1.6 were bit-identical to each other; 1.7 is not bit-identical to 1.6 (largest difference 0.0095 at Sine 0.5 Hz, much more at fast rates where the band now travels further). Edge Q is fixed off. From 1.7 on, `HostSmoke --compare` against the previous build must say "SAMME LYD" again unless the user asks for a change in the sound (1.9 vs 1.8: compared with 1.8's Smooth Peaks on, bit-identical).
- **LFO → band:** every `kChunk` = 32 host samples, the LFO value v (−1..1, `lfoValue` = shape + offset, clipped) moves the band's middle to `log2(freq) + v · amount · 3` octaves (`bandEdgesFor`, clamped to 20 Hz–20 kHz). Then `core.setParams` runs (it designs only band 1's four crossovers, and only when the edges moved), and the chunk goes through the 4× oversampler and `core.process`. The 4× oversampling (60 samples latency) stays: at 1× the top crossovers could not go above 20.7 kHz, which changes the sound when the band is high.
- **Speed limit (1.7):** the band must always reach the ends of the Sweep range at any rate (user, 2026-11-10, like Ableton's LFO Tool). The per-chunk edge limit is `modeMaxSpeed` (40 / 20 / 10 oct/s, `kMaxOctPerSec24/48/96`) **plus** 1.25 × the LFO's own top speed (Sine 2π·A·rate, Triangle 4·A·rate, Square π·A·rate / squareW, Random π·A·rate, A = Sweep · 3 oct), so the LFO is always followed and only jumps (Frequency, Pause release, automation) are slowed by the old limit. `EditorShot <dir> --reach` checks the band's middle reaches 75 Hz – 4.80 kHz (600 Hz, Sweep 100 %) for every mode and shape at 1 and 20 Hz. Cost: at fast rates the pitch bends much more (300 Hz, 12 Hz: 789 / 2335 / 2174 cent for 24 / 48 / 96) and there are short level peaks up to about +9 dB (RMS at most about +2 dB); HostSmoke prints a "Niveau ved fuld fart" table and its level limit is 2.0 for a 0.6 input (instability gave 4.8–27). CPU about the same as 1.6.
- **Before 1.7** each mode's edges moved at most 40 / 20 / 10 octaves per second: twice as steep = half the speed, so the level bumps at Square 20 Hz stayed the same (0.68 / 0.75 / 0.79 for a 0.6 two-tone input). Faster gave level jumps with biquads. Measured in 1.2 (`FREMDRIFT.md`):
  - The level swells and dips along with the pitch in every mode (about 1.5 dB per 200 cent at 300 Hz). That is part of the effect.
  - The delay around the edge doubles per step (band 212–424 Hz: 21 / 41 / 88 ms for 48 / 96 / 192).
  - 192 dB/oct works in the engine but was not added: only about 20–30 % more pitch than 96 at the speed limit, +5 to +11 dB level swing, and bass smeared by up to 0.5 s.
  - A TPT-SVF allpass only helps at extreme speeds (more than 100 octaves per second), so the biquads stayed until 1.7 needed those speeds.
- **Shapes:** Sine, Triangle (in phase with sine), Square with raised-cosine transitions of about 8 ms (`squareW` = 0.008 · rate cycles, ≤ 0.25), Random = a cosine glide from one random value to the next each cycle.
- **Sync:** `syncBeats` (bars use the host's time signature). While the host plays, the phase is `ppq / beats` (locked to the bar); otherwise it free-runs at the host tempo (120 when unknown).
- **Dry/Wet:** the dry signal is delayed by the oversampler's latency (`juce::dsp::DelayLine`, Lagrange 3rd, fractional) and mixed linearly. Between dry and wet the moving allpass phase makes phaser notches.
- **Drawing:** the editor builds `EngineParams` from the band's current edges (`bandLoNow` / `bandHiNow`, written by the audio thread) with a nominal drive of 100 % (`kShowDrive`, the sound has none) and draws `CurveModel::contribPct` for band 1, so the band looks like 1.0 at its default.
